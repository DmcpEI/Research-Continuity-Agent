# Changelog

All notable changes to RCA. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow `pyproject.toml` and are tagged `vX.Y.Z` (1.1–1.4 were never tagged). Entries before 1.5.0 live in git history.

## [Unreleased]

### Security
- The filesystem MCP server's `search_text` passed the model-supplied pattern to ripgrep as a positional argument, so a pattern such as `--pre=CMD` became an rg flag and ran `CMD` on every file in the sandbox. A prompt-injected document could therefore trigger command execution through the agent. The pattern now follows `-e` and the path follows `--`. Upgrade recommended for anyone running agent mode.

### Added
- Test-split scorecard (#5). `eval/harness.py --split test` runs only the questions of one split (and records `split` in the run), and `eval/scorecard.py <run>` turns such a run into `eval/scorecard.json` plus a generated block in README.md and docs/EVAL.md: answered with the expected citation, refused (answerable and unanswerable), citation precision, retrieval hit@5 from the same run, keyword hit rate and time per question, with Wilson 95% intervals and the IDs of every miss. It refuses runs from a dirty tree, a degraded or non-Chroma index, with errored questions, a component that fell back (reranker unavailable, query rewrite failed, facts check failed), questions other than the committed `eval/golden.json` test split, an overridden rewrite model or any non-default setting that grounded chat uses. Harness runs now record each question's trace warnings, the golden file's SHA-256 and the question IDs; run provenance also records `facts_check_enabled`. Eval-only; no runtime change.
- Facts check for hedged answers (#6). When a reply says "the context does not contain ..." or similar, a second call to the chat model lists the statements in it that answer the question; if there are none, RCA declines (`not_found`, label `facts_check_no_answer`) instead of showing the hedge with a citation to a nearby block as a cited answer. On the 40-question test split with `qwen3.5:4b`, unanswerable questions declined went from 6/12 to 12/12 and answerable ones from 1/28 to 2/28; mean time per question rose from 8.6 s to 9.2 s (the check ran on 13 of 40 replies, median 1.7 s). On by default; `RCA_FACTS_CHECK_ENABLED=false` turns it off. If the check call fails, the earlier rule decides and the answer carries `facts_check_failed`. The hedge rule is now one definition (`rca/flows/facts_check.is_hedged`), wider than the old phrase list, so with the check off a hedged reply with a weak citation is declined slightly more often than before. The eval comparison imports the shipped prompt. `LLMClient.chat_json()` asks for a JSON-schema reply (Ollama `format`, OpenAI-compatible `response_format`) and falls back to plain chat for other clients. No `partial` outcome: the classifiers cannot tell partial from full answers reliably (docs/EVAL.md). Affects only code using `GenerateFlow` internals: `_ABSTENTION_SIGNALS` and `_contains_abstention_signal` are removed, and `_decide_abstention` takes the hedge and facts-check results.
- Typed answer outcome. `GeneratedAnswer.outcome` is one of `answered`, `unverified`, `not_found` or `conversational`, and replaces the two independent `grounded` / `abstained` flags, which could contradict each other; both are now derived from it and keep their old values on every path. `/chat` returns `outcome` next to `grounded`. In the React chat a refusal now shows a neutral "No evidence found" badge instead of "⚠ Unverified", a reply about the chat itself shows no badge, and a failed request shows "Request failed"; messages saved before this change keep their old badge. Harness results record `outcome` per question and the summary gains `outcome_counts` (failed questions count as `error`). Affects anyone constructing `GeneratedAnswer` directly: `outcome` is required, and `grounded=` / `abstained=` arguments are ignored. No migration for stored data.
- Answer classifier comparison for #6: `eval/compare_answer_classifiers.py` scores the current abstain decision, a hedge-phrase rule and two `qwen3.5:4b` verifier prompts against labels drafted under the rules agreed with the author, split by answerable and unanswerable questions. New labels cover every full-text `qwen3.5:4b` answer on the dev (76) and test (35) splits (`eval/answer_labels_fulltext_dev.json`, `eval/answer_labels_fulltext_test.json`). Of the 8 test-split non-answers that get past the pre-generation gates, the current decision catches 1; a verifier that lists what the answer actually gives catches all 8 and keeps 26 of 27 useful answers, at about 3.5 s per checked answer. Results and caveats in docs/EVAL.md. Eval-only; no runtime change.
- Answer outcome labels for #6: `eval/sample_answer_labels.py` draws saved harness answers (weighted towards hedged ones, gate answers excluded) and `eval/answer_labels.json` holds 100 labelled answers (`answered` / `partial` / `not_found`, plus `unsupported`, `contradictory` and `missed_in_context` flags), judged against the 240-character excerpts the model actually sees. Labelling rules and first results are in docs/EVAL.md: the current abstention decision catches 13 of 51 `not_found` answers. `eval/results/*/` is now gitignored so local run folders are not committed by accident. Eval-only; no runtime change.
- One-command public demo: `docker compose up --build demo` (or `make demo`) checks host Ollama, downloads five CC BY 4.0 arXiv papers listed in `demo/papers.json`, ingests them, and serves the React app plus API on `localhost:8000` (#15). New `create_site()` in `rca/api/main.py` mounts the API under `/api` and serves `frontend/dist` with an `index.html` fallback for client-side routes (`RCA_FRONTEND_DIST`). Demo data lives in Docker volumes, not `./.rca`. README gains "Results at a glance" and "Try the demo" sections. The `demo` service sits behind a compose profile, so a bare `docker compose up` still starts only Streamlit; stop it with `docker compose --profile demo down`. Also: the Streamlit `rca` compose service no longer fails when `.env` is missing, and `frontend/node_modules`, `.claude/` and `CLAUDE.md` are no longer sent to the Docker build context.
- Retrieval regression gate in the pytest job (CI and pre-push): a synthetic 12-note corpus and 27 questions run through GenerateFlow's retrieval call without Ollama (JSON vector backend, no reranker or rewrite), and the test fails if any question ranks worse than in `tests/fixtures/retrieval_gate/baseline.json`, printing hit@5, MRR, and each question whose rank moved (#8). It catches breakages of FTS5 candidates, lexical scoring, and ordering. Baseline hit@5 96.3%, MRR 0.717. Contributors: after a deliberate retrieval change, refresh with `RCA_UPDATE_RETRIEVAL_BASELINE=1 uv run pytest tests/integration/test_retrieval_gate.py` and commit the baseline diff. Does not cover rewrite, rerank, embeddings, or most query-type weights; see docs/EVAL.md.
- Agent benchmark `eval/run_agent_eval.py` with 20 sandboxed tasks (`eval/agent_tasks.json`, fixture `eval/agent_fixture/`) scoring task success, tool selection, tool precision, steps, invalid calls, and stop reasons (#13). First run with `qwen3.5:9b`: 12/20 tasks, tool selection 16/18. Eval-only; no runtime change.
- Run provenance in every eval artifact: corpus fingerprint, exact Ollama model digests and server version, reranker revision, result-affecting settings, git commit, and vector-backend state at start and end with an `index_degraded_during_run` flag (#10). Harness traces now fill `corpus_version`. Affects eval artifacts only.
- CI job for the frontend on Node 24: type-check of app and tests (`tsconfig.test.json`, tests were previously excluded from type-checking), production build, and vitest; the pre-push hook runs the same commands (`npm run typecheck`, `npm run build`, `npm test`) and stops with a clear message if `frontend/node_modules` is missing. Node version lives in `frontend/.nvmrc`. Contributors: run `npm ci` in `frontend/` once.
- Git hooks via the `pre-commit` framework: ruff check + format check on commit, the CI pytest command on push. Contributors: run `uv run pre-commit install` once per clone.
- Harness failure-stage taxonomy (`retrieval_miss`, `context_miss`, `false_abstention`, `citation_miss`, `false_answer`) with per-case retrieved/context sources and abstention per `negative_type` (4e87a4f). Affects eval artifacts only.
- Production-path retrieval ablation (config 5) mirroring `GenerateFlow`; refreshed metrics: 96.7% hit@5 / 98.9% hit@10 on 90 answerable questions (d609169).
- Retrieval-feature abstention calibration scripts `eval/collect_retrieval_features.py` and `eval/calibrate_abstention.py` (0058f36).
- 29 typed negative questions (`neg-011`–`neg-039`); golden set is now 129 questions with 39 negatives (639c60b).

### Changed
- React UI now draws every colour, font size, spacing value, radius and duration from one token file, `frontend/src/styles/tokens.css` (docs/DESIGN.md, step F1). Before, the stylesheet used 24 hex and 56 `rgba()` colours, 19 font sizes and 21 radii; secondary text was 3.6–3.8:1 against its background at 10–11 px. Now all HTML text is at least 4.5:1 and 12 px (the knowledge-graph labels are SVG and stay at 9 px until DESIGN.md question 1 decides whether the graph stays), keyboard focus shows one 2 px accent ring, hover is a neutral tint and selection the accent, delete actions are red instead of amber, graph nodes are accent for papers and grey for every other kind (notes and experiments were green and amber, colours that now mean answer outcomes only), and animations stop under the system's reduced-motion setting. `tokens.test.ts` fails on raw colours (hex, colour functions, common names), lengths off the spacing and type scales, and literal durations anywhere outside the token file; it is a tripwire for the usual forms, not a full CSS parser. Also fixed: the model button's disabled style never applied (a missing brace nested it inside another rule). Removed the unused `tailwindcss` dev dependency and its config. Affects anyone styling the UI: use the tokens.
- Grounded chat now gives the answer model the full text of each retrieved chunk (about 1,100 characters) instead of its first 240 characters, which often cut off the sentence that answered the question. The post-generation citation support check reads the same text. On the dev split with `qwen3.5:4b`, real cited answers rose from 40 to 51 of 62 answerable questions, refusals that cite a nearby block fell from 18 to 6, and the answer keyword hit rate from 0.26 to 0.48. Costs: prompts roughly double (about 2,200 tokens per answer on average, max about 2,700; `qwen3.5:4b` accepted a 29k-token prompt in a probe, so context length is not a limit for the default model) and answers take about 3 s longer. The citation support check now compares against the full text too, which makes it even more lenient (see docs/EVAL.md). The reranker, the rerank-gate threshold and the UI excerpt are unchanged; the agent's knowledge-base tool still returns 240-character excerpts. Affects chat answers and eval results.
- Grounded chat prompts now show the exact citation tag on every context block (`(cite as [[id]])`) and repeat the citation rule after the question, because small models answered in uncited prose that failed the grounding check. On the dev split, real cited answers from the default `qwen3.5:4b` rose from 21 to 40 of 62 answerable questions. Known cost: the model now also cites when it says the context lacks the answer, and such hedged answers with valid citations count as answers, so it refused 12 of 27 unanswerable questions (was 25) and the UI can show a refusal as a grounded answer; fix tracked in #6. Affects chat answers and eval results for every model; prompts grow by about 30 tokens per context block plus about 45 for the reminder. See docs/EVAL.md.
- Default chat and agent model is now `qwen3.5:4b` for both (was `gemma3:12b` for chat and `qwen2.5:14b` for the agent), so only one 4 GB chat model is in memory instead of two large ones; `gemma3:12b` left an 18 GB laptop at 2-4% free RAM and cannot call tools. Chosen in a six-model bake-off on the dev split and the agent benchmark (docs/EVAL.md): best agent result of the six (17/20 tasks, tool selection 17/18). Chat gets worse with the current prompt, because the model often omits `[[...]]` citation tags: grounded 0.78 → 0.28, citation precision 0.98 → 0.49, answerable questions wrongly refused 4 → 15 of 62. Retrieval hit@k and the rerank-gate threshold were measured with `gemma3:12b` query rewrites and are not re-measured. Migration: run `ollama pull qwen3.5:4b`. A `.env` copied from the old `.env.example` still sets `RCA_GENERATION_MODEL=gemma4:e4b`; remove that line. The React app remembers the last chat and agent model per browser and re-selects it, so pick `qwen3.5:4b` in the model picker once. To keep the old models, set `RCA_GENERATION_MODEL` / `RCA_AGENT_MODEL`. `.env.example` and the demo compose service now use the same default.
- Ollama now unloads RCA's chat, agent and embedding models 1 minute after the last request instead of Ollama's default 5 minutes, so RAM is freed sooner on laptops that also run other work. Set `RCA_LLM_KEEP_ALIVE` (seconds or a duration such as `30s`, `5m`; `-1` keeps models loaded) to change it; an invalid value now fails at startup instead of on every request. The agent tab's tool-calling probe, which loads every installed model once, now unloads each model as soon as it answers (previously each stayed in RAM for 5 minutes). The first question after an idle minute pays the model load time again (a few seconds for small models). OpenAI-compatible backends are unaffected.
- When hit `k` would repeat a paper already shown, retrieval gives the last slot of the top `k` to the best-ranked unseen paper, so one paper's chunks are less likely to crowd out a second relevant paper (#9). Only candidates with rerank score above `-6.0` qualify (`RCA_RETRIEVAL_RESERVE_MIN_RERANK_SCORE`). Production hit@5 96.7% → 98.9% on 90 answerable questions; cross-paper questions 75% → 87.5%. Affects chat, agent search, and eval results; same-paper chunks in a 5-hit context drop from ~4.1 to ~3.8 on average. Disable with `RCA_RETRIEVAL_RESERVE_NEW_SOURCE=false`.
- Grounded chat abstains before the LLM call when the top cross-encoder rerank score is ≤ −3.618 (labels `low_rerank_score`, `low_retrieval_confidence`) (e9fd29d). Affects chat users and eval results: clearly out-of-corpus questions now return a refusal faster. The threshold is tied to `cross-encoder/ms-marco-MiniLM-L-6-v2`; recalibrate if the reranker changes.

### Fixed
- A refusal could be empty. When the model replied with nothing, whitespace or only a citation tag and retrieval confidence was low, `/chat` returned `outcome: "not_found"` with an empty `answer` and the chat showed an empty bubble. It now says "I couldn't find evidence for this in your knowledge base.", the same text as the rerank gate. Affects API clients that treated an empty `answer` as a refusal: check `outcome` instead.
- React chat: a failed request was treated like an answer. Its error text and the question it failed on were sent back to the model as conversation history with every later question. Both are now left out (refusals are answers and are still sent), and the latest failed request has a Retry button that removes the failed pair and sends the same question again. Conversations saved earlier need no migration: old error bubbles, including those saved before outcomes existed (recognised by their `msg-error-` id), stay visible, are skipped as history and can be retried.
- `eval/compare_answer_classifiers.py --verifier` crashed with `AttributeError` when no generation model was set, and with `RCA_LLM_BACKEND=openai_compatible` it posted Ollama-only requests that all failed as missing predictions. It now stops at once with a message saying it needs the Ollama backend. Eval-only.
- The agent passed knowledge-base source IDs (`src:...`) to filesystem tools as if they were files (#22). Filesystem tools now intercept `src:`/`chk:` paths (also in `[[...]]` form) and return guidance to answer from the search excerpts and cite the source; the knowledge-base tool description and system prompt say source IDs are citations. Redirected calls, and the existing `.pdf` redirect, now report status `error`, so the agent benchmark counts them as invalid calls (previously they looked successful). Tool-call arguments that are valid JSON but not an object are rejected with a warning instead of crashing the agent run.
- Thinking models (e.g. `qwen3.5:9b`) returned their whole answer in Ollama's `message.thinking` with empty `content`, so chat answers came back empty and the agent replied "I could not produce an answer..." even after fetching the right data (#21). Ollama requests now send `think: false` by default (`RCA_LLM_THINK`, only `true` for thinking-capable models). Agent benchmark with `qwen3.5:9b`: 12/20 → 19/20 tasks, mean latency 24 s → 11 s. Also: empty final turns stop as `empty_final_answer` and undecodable tool calls with no text as `unparsed_tool_call` (new values in agent traces and eval `stopped_reasons`); HTTP errors from the LLM client now include the server's message; a rejected `think: true` is no longer misreported as missing tool support.
- A Chroma → JSON vector-store fallback is now visible: `/status` returns `vector_backend` and `warnings`, the React status bar shows a "Vector search degraded" badge (status refreshes every 30 s), and the Streamlit sidebar shows a warning. Previously it was only logged, so retrieval could silently degrade (#17, #2). API consumers: two new additive fields, no migration.
- Agent knowledge-base search now uses the same retrieve flow and vector store as chat (API and Streamlit), so a vector fallback hit by the agent shows up in `/status` and the UI. Previously the agent built its own store. `ToolRegistry` and `AgentLoop` accept an optional `retrieve_flow` (passing it together with `knowledge_base_search` or `registry` raises `ValueError`); Streamlit clears the cached agent loop whenever it rebuilds the chat flows after an ingest. Existing callers are unaffected.
- Integration tests no longer load the real cross-encoder, which made Hugging Face Hub requests and could stall the pre-push hook for over a minute on a slow network. Contributors only; reranking stays covered by a stubbed unit test.

### Removed
- The ingest event log. Every ingest appended a line to `.rca/events.jsonl` and nothing ever read it. Ingest no longer writes it; `IngestFlow` loses its `event_log` argument and settings lose `event_log_path` (`RCA_EVENT_LOG_PATH` is now ignored). Existing `events.jsonl` files are left on disk; delete them by hand if you like.
- Code nothing imported: `rca.orchestrator` (intent router and tool-policy checks), `rca/config/tool_policies.yaml` and the `tool_policy_path` setting (`RCA_TOOL_POLICY_PATH`) only it read, `rca.telemetry.metrics`, `rca.telemetry.tracing`, the empty `rca.mcp_servers.arxiv` package, and the direct `PyJWT` dependency. No runtime change; an old `.env` that still sets `RCA_TOOL_POLICY_PATH` keeps working, because unknown settings are ignored. Affects only code importing these modules.
- Empty `rca.mcp_servers.git` and `rca.mcp_servers.zotero` placeholder packages (#14). They held no code; nothing imported them. Zotero is no longer listed as planned work.

## [1.5.0] - 2026-09-29 (tag `v1.5.0`)

### Added
- Document revisions and idempotent re-ingest keyed on file and content hashes; additive `source_revisions` table, no migration needed for existing databases (446f9d5).
- FastAPI backend for the React frontend: sources with revisions, ingest, chat, agent, model selection with tool-capability probing, inline PDF (07be586).
- Generation failure labels and grounding check; harness `--model`, `--rewrite-model`, `--strict-model-check`, `--external-golden-path` (68716b5).
- Conversational queries (chit-chat) skip retrieval, and chat prompts include prior conversation turns (68716b5).

### Changed
- Uncited answers are no longer marked grounded by injecting the top source as a citation (68716b5).
- Default generation model is `gemma3:12b`; agent model `qwen2.5:14b` (07be586).

### Fixed
- Frontend tests on Node 25+, where the built-in `localStorage` shadowed jsdom's (3f3cc7f).
